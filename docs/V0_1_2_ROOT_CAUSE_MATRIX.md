# V0.1.2 root-cause matrix

This matrix was prepared against `main` at merge commit
`ccf0adf589d168e1c5ead4358acd53160f4c2479` before V0.1.2 implementation.

| Confirmed symptom | Exact code/storage cause | Required correction | Preservation guard |
|---|---|---|---|
| Thousands of Recorder temperature states but only 57 hourly and 3 daily summaries | Schema V4 `temperature_summaries` rows are keyed to `hourly_records`/`daily_records`. `async_reprocess_temperature_history()` skips a date with no energy parent, while `merge_hourly_temperatures()` and `merge_daily_temperatures()` return `False` when the parent is absent. | Add independent temperature-only hourly/daily storage and make reads overlay it onto energy records or expose virtual temperature-only records. Backfill from one bounded Recorder query per physical entity/day. | Never insert synthetic energy rows or update energy, allocation, PV/grid, checkpoint or energy checksums. |
| Repair reports 0 changes with no errors and UI shows green | The repair result has no outcome contract beyond `error_count`; the frontend maps `error_count == 0` directly to CSS `good`. Mapping skips are returned but not rendered. | Return inserted/updated/unchanged/skipped/failed counts, before/after coverage and exact reasons. Treat zero recovery with remaining recoverable gaps as `action_required`. Separate diagnose, existing-record repair and temperature-only backfill actions. | A no-op remains idempotent but is not called successful recovery when gaps remain. |
| Heating Electricity is `—` at an 08:00 cutoff despite about 4.0 kWh known heating | `combine_interval_records()` reduces any non-`good` allocation (including valid `uncertain`) to `partial`; `canonical_energy().kind_complete()` then withholds complete category totals. The KPI renders the complete value as the main amount and the known subtotal only as secondary text. | Preserve `uncertain`/`filtered` classification quality when interval coverage and meters are complete. Publish complete-through-cutoff separately from calendar-day finalization. Render the known provisional subtotal as the main value when a strict total is unavailable, with confirmed/selected/estimated evidence retained. | Missing values remain unavailable, selected/estimated energy is never promoted to confirmed, and completed historical semantics remain strict. |
| Current day previously showed `missing` and `partial` together | Frontend quality labels mixed calendar finalization, meter evidence, classification evidence and temperature evidence. | Keep independent elapsed-period, calendar-day, meter, classification and temperature statuses; an intentionally partial date is not a missing meter. | Do not let unrelated temperature gaps invalidate electricity totals. |
| Temperature card can show 100% and unclear `partial` | Combined temperature quality requires all child labels to be exactly `good`, so complete filtered evidence can become `partial`; the UI does not label the coverage scope. | Derive quality from validated elapsed seconds and separately expose complete-through-cutoff, response eligibility and full-calendar-day completeness. | Rejections remain visible and no gap is filled. |
| Historical mapping may block valid periods or reuse an obsolete date | V4 `mapping_revisions.checksum` is unique and `ensure_mapping_revision()` returns the first identical mapping. An A→B→A sequence therefore reuses the first A occurrence. Repair has no explicit attestation path for periods before recorded mapping history. | Add chronological mapping events that allow repeated identities, resolve the event active for the full interval, and support bounded explicit administrator attestation. | Never assume the current mapping applied historically; conflicts and absent evidence remain explicit skips. |
| Same physical entity can be collected more than once under logical roles | Recorder history is entity-deduplicated, but normalization/diagnostic accounting is per logical source and backfill has no independent source store. | Query each physical entity once per bounded day, then calculate and persist each logical source independently with its own role/quality/provenance. | Logical identities remain distinct; source/entity/attribute/role provenance is retained. |
| Energy-season controls render as sliders with invisible values | General flow uses raw numeric validators rather than localized month select and visible number selectors. | Use localized month dropdowns and a visible 1–28 numeric selector with an explicit localized preview. | Preserve 170 m² and all mappings/options unless the user changes them. Season changes do not rewrite history. |
| HACS update served stale V0.1.1 JavaScript | Manifest and `VERSION` remained 0.1.1, and the panel query parameter is only `VERSION`. | Release 0.1.2 and include a deterministic frontend content/build token in the module URL. | Sidebar path stays `/home-energy-intelligence`; no config-entry recreation is required. |

## Implementation constraints

- Recorder and InfluxDB remain read-only.
- UTC interval keys are authoritative; Home Assistant local dates may be 23, 24 or 25 hours.
- Temperature backfill is bounded to 1–31 inclusive days and never processes future hours.
- Existing V4 energy and allocation records, checksums and revisions must remain byte-for-byte unchanged during temperature-only backfill.
- No thermal output, COP, design-day load or forecast is inferred.
