# V0.1.1 dashboard and intraday architecture

V0.1.1 adds a compact hourly layer beside the existing six-hour checkpoints and authoritative 05:00 daily close. Every completed elapsed UTC hour is stored once by `(interval_start_utc, interval_end_utc)`. The local date and timezone are retained, so 23- and 25-hour days are represented without ambiguous local keys. Startup recovery scans only yesterday and today; normal dashboard reads query compact SQLite rows and do not rescan Recorder.

## Canonical presentation contract

`analytics.canonical_energy()` is the only category interpretation exposed to Overview, History and CSV. It preserves confirmed heat-pump heating, assumed heat-pump heating, confirmed/selected/estimated AC heating, DHW, cooling, idle, unknown, raw residual evidence, other household electricity and reconciliation discrepancy separately. Per-equipment rows are generated from stable configured IDs and names. Missing equipment data makes the period incomplete rather than producing a false zero.

Every category distinguishes a complete measured/calculated value from a known partial subtotal. A confirmed zero is emitted only when the required equipment allocations and meters are present. Missing equipment or interval evidence produces an unavailable public total plus explicit `known_*` evidence. The same contract is used by cards, tables, charts and CSV.

PV calculations require all relevant non-negative inputs and reject export greater than generation. Missing or physically invalid inputs leave self-consumption and self-sufficiency unavailable.

## Temperature contract

Indoor and outdoor cards use the same `time_weighted_temperature()` result. Recorder state changes are weighted by elapsed seconds; explicit unavailable states and rejected intervals create gaps. Latest validated value and timestamp are distinct from the period mean. Longer ranges combine `mean × valid_coverage_seconds` across intervals, with validated min/max and total coverage. They never average rounded daily means.

Representative indoor and outdoor sources are stable source IDs selected in Options Flow. No entity ID or equipment name is embedded in calculations or the panel.

## Coverage and selected periods

Overview builds Today and Yesterday-to-the-same-local-cutoff only from persisted hourly rows. It enumerates the expected elapsed UTC hours, detects internal gaps and marks the result partial even when the newest interval exists. Manual refresh retries missing and poor rows and may reprocess an aged partial row after delayed Recorder values arrive; the unique interval key keeps this idempotent.

History period bounds are resolved on the backend using Home Assistant's configured timezone. Calendar weeks are Monday–Sunday, months and years are calendar periods, and the energy-season boundary is configurable (July 1 by default). The summary reads the complete bounded range, while detail rows remain paginated. Missing dates and poor-quality dates are explicit. CSV uses the same selected bounds and is not limited by the detail page size.

## Migration and rollback

Schema V4 normalizes temperature summaries and hourly rejection evidence rather than repeating large audit arrays in daily/hourly JSON blobs. The migration runs in one immediate transaction, preserves logical record contents, checksums, revisions, allocations, checkpoints, mapping revisions, job metadata and configuration, and updates `schema_version` only after every row is converted. Injected-failure tests prove rollback to readable V3 inline rows. Freed pages are compacted only after commit. Take the administrator-only protected database export before changing versions; older code must not be used to write a V4 database.

## Refresh and access

An hourly job runs shortly after the hour. Manual refresh uses the authenticated Home Assistant WebSocket connection and idempotently fills missing bounded intervals. Overview retains its prior response if a browser refresh call fails and identifies stale data. Settings remain administrator-only; Overview, History and selected-range CSV use authenticated Home Assistant users. The database backup service remains administrator-only and never publishes under `/config/www`.
