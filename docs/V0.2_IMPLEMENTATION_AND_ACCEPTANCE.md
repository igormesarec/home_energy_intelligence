# Home Energy Intelligence V0.2 implementation and acceptance

## Scope and dependency

V0.2 is a dependent draft built on the V0.1.2 correction head. It preserves the
hourly Recorder pipeline, schema V5 temperature history and the four V0.1.2 dashboard
tabs. It must not be merged before the V0.1.2 base is accepted and the dependent branch
is rebased or retargeted cleanly.

## Measurement rules

- Cumulative heating/DHW thermal generation may come from configured Home Assistant
  entities or an administrator's manual meter log.
- The source timestamp is authoritative. DST gaps are rejected and ambiguous wall times
  require the first/second occurrence. The first reading is only a baseline.
- Differences are computed only between consecutive observations of the same stable
  Ecodan equipment and meter identity. Decreases remain reset/correction evidence.
- A COP requires measured thermal generation and complete classified Ecodan electricity
  over exactly the same UTC boundaries. Assumed heating, DHW cross-allocation and every
  AC value are excluded. Combined COP is a ratio of sums.
- Sparse multi-day readings stay multi-day interval points. They are not divided into
  daily heat, and no missing period is interpolated.

## Four functional response charts

1. Ecodan space-heating electricity, measured heat and visible interval heating COP.
2. Ecodan plus each enabled AC's heating electricity, combined kWh/day and kWh/m²/day.
3. Each enabled AC's cooling electricity, combined kWh/day and kWh/m²/day.
4. Ecodan DHW electricity, measured DHW heat and visible interval DHW COP.

All charts use the selected representative measured-outdoor source and the shared period
controls. The default floor area for a new setup is 170 m²; saved values are not changed.

## Migration and rollback

Schema V6 adds `thermal_meter_readings` and `thermal_meter_reading_audit` without
rewriting existing daily, hourly, checkpoint, mapping, temperature, allocation or
checksum rows. Before installation, create a protected SQLite backup. Rollback restores
the integration and database backup together; do not delete or rebuild the database.

## Installation

1. Back up Home Assistant and use the integration's protected SQLite backup mechanism.
2. Install the dependent V0.2 draft through a test HACS/custom-components environment.
3. Restart Home Assistant and confirm Settings reports schema 6.
4. Open integration Options → Data sources and measured thermal energy.
5. Select manual-only, Home Assistant counters or mixed mode, the Ecodan stable equipment
   ID and any cumulative thermal sources. Do not select circuit 2K or a flow-temperature
   sensor as thermal energy.
6. Use **COP & Efficiency** to add a second cumulative observation or run a bounded
   Recorder backfill. Confirm the first reading remains a baseline and interval bounds,
   sources, units and quality are displayed before accepting any COP.

## Automated evidence

The branch runs the complete Python suite, schema migrations, Python compilation,
JavaScript syntax validation and executable Node rendering of the four response curves.
Home Assistant runtime tests must also pass in GitHub Actions before review.

## Required live acceptance and current NO-GO

Automated fixtures are not production validation. On a backed-up non-production Home
Assistant instance, an administrator must verify config/options reload, Recorder thermal
source history, manual edit/delete audit behavior, schema migration, real desktop/mobile
rendering, exact interval boundaries and comparison with physical Ecodan/Shelly meters.
Until that is complete, V0.2 is **NO-GO**, draft and unmerged.
